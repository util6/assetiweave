# 领域文档

本文件说明工程技能在探索代码库时如何使用本仓库的领域文档。

## 探索前按需读取

- 根目录的 `CONTEXT.md`；或者
- 若根目录存在 `CONTEXT-MAP.md`，先读取它，再读取与当前主题相关的每个 `CONTEXT.md`；
- `agent-docs/adr/`：读取与当前工作区域有关的 ADR。在多上下文仓库中，还应检查对应上下文的 ADR 目录。

这些文件或目录不存在时静默继续；不报告缺失，也不主动建议创建。`/domain-modeling` 技能会在术语或决策真正明确时按需创建它们。

## 文件布局

本仓库采用单上下文布局：

```text
/
├── CONTEXT.md
├── docs/                       # 用户文档与长期知识
├── agent-docs/
│   ├── adr/                    # 经提炼的架构决策
│   ├── governance/             # Agent 运行规则
│   └── feature-plans/          # 工作材料，不是当前事实
└── src/
```

## 使用词汇表术语

当输出涉及领域概念时——例如 Issue 标题、重构建议、假设或测试名称——使用 `CONTEXT.md` 中定义的术语，避免使用词汇表已明确排除的同义词。

若所需概念不在词汇表中，先判断是否偏离了项目既有语言；若确属合理缺口，记录给 `/domain-modeling` 处理。

## 标注 ADR 冲突

输出若与现有 ADR 冲突，必须显式说明，而不是静默覆盖：

> 与 ADR-0007（<决策名称>）冲突，但因……值得重新讨论。

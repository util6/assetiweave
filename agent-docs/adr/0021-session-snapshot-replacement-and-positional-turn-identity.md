# 0021: 会话快照整包替换与轮次位置身份

> **状态**：已接受（部分取代 ADR-0006 中轮次增量对账与持久化问题聚合的约定）
> **决策日期**：2026-11-06

第三方对话适配器每次返回的都是整个会话的完整快照，且现代宿主普遍支持回滚、重生成与分支切换；此前在 `conversation_turns` / `web_record_turns` 上持久化 `external_id`、`fingerprint`、`missing` 做逐轮对账与事后修剪，迫使各适配器拼凑不稳定的源侧标识（`turn-N` 与源消息 ID 混存），并在回滚时引发主键漂移与引用撕裂。

我们决定将同步与版本判定的粒度统一收口在会话级（`conversation_session_observations.synced_version`）：一旦会话版本变化，在单事务中按会话整体清理并重写该会话的轮次、内容事实与全文索引（接受替换时物理清空局部翻译文本）；物理删除轮次表的 `external_id`、`fingerprint`、`missing` 三列，由核心按过滤后的顺序统一赋 `turn_index = 0..N` 并以 `sha256(session_id, turn_index)` 生成轮次主键，同时强制 `started_at` 非空以区分回滚重聊后的新轮次。

## 备选方案与取舍

- **保留源消息 ID 或新增 `conversation_turn_identities` 映射表**：并非所有宿主都为每轮交互提供稳定消息 ID（如基于步骤表或纯流式日志的宿主），把复杂度搬到独立映射表仍需启发式匹配且无法消除回滚时的残留与错位。
- **在主键哈希中混入内容摘要或时间戳**：Memory 节点锚点（`<short_id>#T<turn>`）与前端路由天然按位置寻址；让主键纯粹表达“某会话的第几轮”、让非空的 `started_at` 表达“何时发生”，职责正交且不会造成主键与上层锚点脱节。

## 后果

- **收益**：轮次表从 14 列收缩为 11 列纯业务事实表；彻底解除适配器提供稳定轮次外部 ID 的负担（`external_id` 降级为导入期内存可选临时键，仅用于解析子代理 `parent_external_id`）；用量事件通过 `turn_index` 归因；FTS5 索引由逐轮回读全表扫改为会话级单次清理与内存直写。
- **约束**：存量数据库需在迁移后由 Rust 修复钩子按会话重排 `turn_index` 并原地重算 `turn.id`（级联更新 Parts 的 `turn_id`/`id_key` 与 `process.parent_turn_id`），以保护源文件已删除的离线会话不丢失；Memory 等消费方判断回滚后的增量轮次时，应结合 `started_at` 时间戳而非仅看轮次总数。
- **索引修复的边界**：`conversation_part_fts` 是会话级文本语料，检索只按 `session_id` 定位、按 `text` 匹配，`turn_id`/`part_id` 是无消费方的 UNINDEXED 派生列。按它们过滤在 FTS5 上必然全表线性扫描（26 万行实测单次 3.4 秒），逐轮重建会让升级在启动阶段卡住数十分钟，因此修复钩子不改写索引行：轮次主键变化不影响任何一行的文本归属，该会话下次整包替换时会整体重写。

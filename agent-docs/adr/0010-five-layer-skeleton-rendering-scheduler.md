# 0010: 五层渲染调度与统一 Skeleton 架构（解决高速滚动白屏与闪烁）

> 状态：已接受
> 决策日期：2026-08-16
> 决策证据：`d2d2b18`, `efd2a1f`, `01a00882`
> 记录日期：2026-08-25

## 背景

在长会话详情预览中，页面往往包含成百上千个 Turn 以及大量复杂的 Markdown 富文本、代码 Diff 高亮、命令执行日志等重型 DOM 结构。

在引入常规虚拟滚动后，用户在高速滚动时遇到了系统性渲染问题：
1. WebKit 合成器在快速滑动时来不及完成复杂 Diff/Markdown 的实时布局，频繁闪烁出透明背景并出现剧烈白屏（Blank Flash）。
2. 高度从占位变为真实内容时产生剧烈的高度跳动（Height Jitter）。

## 决策

建立通用的五层渲染架构体系（Rendering Strategy）：

1. **Layer 0 - 不透明滚动表面（Opaque Scroll Surface）**：提供底层不透明基底，阻断 WebKit 合成器背景穿透与闪白。
2. **Layer 1 - 虚拟化视口（Virtualized Window）**：仅渲染视口范围内的 Turn，严格控制 DOM 总节点数。
3. **Layer 2 - 预加载超视口（Overscan Buffer）**：提前预备即将进入视口的内容。
4. **Layer 3 - 骨架占位屏（Skeleton Placeholder）**：在真实组件未完成测量或来不及渲染时，一律以固定尺寸的 Skeleton 占位，**宁可展示骨架，绝不呈现空白**。
5. **Layer 4 - 共享渲染调度器（Render Scheduler）**：监听滚动活动状态。高速滚动时主动降级为轻量 Skeleton，滚动静止（Idle）后调度微任务平滑升级为完整富文本渲染。
6. **Layer 5 - 尺寸高度缓存（Size Cache）**：缓存测量高度，彻底消除从 Skeleton 切换到 Real 时的视口跳跃。

## 备选方案

### 针对每个组件单独写懒加载

- 缺点：分散在几十个业务组件中的零散防抖与加载态无法协同，滚动时依然各行其是，开发与维护成本巨大。
- 结论：否决。

## 后果

- 即使面对 10,000+ 轮次的极端巨型会话，在快速拖拽滚动条时界面也始终丝滑稳定，彻底根治了白屏闪烁问题。

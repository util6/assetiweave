# 0003: 面向工作场景的分组（Asset Group）与一键互斥装配（Exclusive Mount）

> 状态：已接受
> 决策日期：2026-06-01
> 决策证据：`af1b2e0`, `019e8b79`
> 记录日期：2026-08-25

## 背景

随着开发者沉淀的 Skill、Prompt、Rule 数量剧增（从几十个增长到上百个），点对点逐个勾选挂载变得极其繁琐。更严重的是，全量将所有资产预装到 Agent 会造成 Context Window 严重膨胀、Prompt 噪音过大以及 Tool 幻觉与冲突。

用户需要能够根据当前的工作场景（例如“前端 React 开发”、“Rust 底层排障”、“代码评审”、“数据分析”）按需装配能力。

## 决策

1. **面向场景的资产分组（Asset Group）**：引入分组模型，支持通过动态匹配规则（Glob 路径、Source 来源）与手动勾选将特定场景所需的资产聚合为一个逻辑单元。
2. **一键互斥挂载（Exclusive Mount）**：引入互斥部署意图。当用户为目标 Profile 激活某个分组的互斥挂载时，系统自动将该组所有资产挂载，并同步移除该 Profile 中不属于该组的其他同类已挂载资产。
3. **组合叠加挂载**：在非互斥模式下，支持用户向目标 Profile 叠加挂载多个场景分组，实现灵活的能力组合。

## 备选方案

### 纯静态文件夹/子目录分类

- 缺点：资产只能属于单一物理文件夹，无法在多个不同工作场景之间复用同一项通用能力（如通用 Git 审查工具）。
- 结论：否决。

### 仅提供多选批量挂载（Batch Additive Only）

- 缺点：在从一个专业场景切换到另一个完全不同的场景时，用户必须先手动找到上一场景的所有资产并逐一卸载，无法一键保持上下文纯净。
- 结论：否决。

## 后果

- Agent 上下文环境可以根据任务一键纯净切换，彻底解决了“大而全工具包”导致的上下文污染问题。
- `AssetGroup` 成为后续资产调度与 CLI 批量操作的核心颗粒度。

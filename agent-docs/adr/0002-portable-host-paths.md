# 0002: 分离可移植路径、解析路径与展示路径

> 状态：已接受
> 决策日期：2026-07-17
> 决策证据：`60987c228b82b6d3c932a577e2810d2fe6f8c9c3`
> 记录日期：2026-07-17

## 背景

AssetIWeave 主要在 macOS 上开发，但管理的配置与文件必须同样支持 Windows 和 Linux。如果直接持久化诸如 `/Users/alice/...`、`~/Library/Application Support/...` 或 `C:\Users\Alice\AppData\...` 等路径，会将记录与创建它的具体机器及操作系统强行绑定。此外，让前端组件随意缩写绝对路径也会导致 `~` 的展示不一致，并且可能泄漏用户隐私（如用户名）。

不同宿主系统的文件系统行为并不相同。特别是在 Windows 上：路径比较不区分大小写、目录符号链接必须使用 `remove_dir` 删除，且创建符号链接可能需要开发者模式（Developer Mode）或提升的管理员权限。

## 决策

在整个应用程序中明确区分三种路径语义：

- **存储路径（Stored path）**：持久化配置使用可移植的通用文本。用户主目录使用 `~`；宿主专属目录使用 `@config`、`@local-data`、`@data` 或 `@cache`。在所有平台上，存储路径的分隔符统一使用 `/`。
- **解析路径（Resolved path）**：绝对路径 `PathBuf` 仅在 I/O 边界通过 `HostPathResolver` 或 `path_utils::expand_path` 解析生成。
- **展示路径（Display path）**：DTO 显式暴露由后端生成的 `display_*` 字段。运行时的绝对路径字段依然保留以支持在文件管理器中定位（Reveal）和底层文件系统操作，但普通的 UI 文本一律使用展示字段。

具体职责划分规则：

- `backend/host_paths.rs`：负责解析路径锚点、规范化存储输入、针对当前宿主环境解析路径并生成展示文本。
- `backend/app_paths.rs`：维护所支持应用程序的默认路径规则。
- `backend/host_filesystem.rs`：负责特定平台的文件系统路径比较、包含关系判定、符号链接的创建/删除、安全路径段校验以及目录复制遍历行为。
- Repository 与配置写入边界：在持久化之前对包含路径的配置进行规范化处理。现存的 Tenant 记录在数据库初始化启动时完成规范化迁移。
- 观测到的运行时数据：例如扫描到的资产绝对路径和物理挂载观测结果，可保持绝对路径形式，因为它们反映的是当前宿主机的即时状态。这些字段不得直接作为常规 UI 展示文本。
- 外部适配器：即便对应的数据库或配置值为锚点格式，适配器边界依然接收解析后的绝对源路径与运行时路径。

Windows 平台的行为通过原生 Windows CI 任务强制保障，包括断开损坏的目录符号链接的删除操作。macOS 上的交叉检查不作为 Windows 文件系统行为验证的充分证据。

## 备选方案

### 所有路径一律持久化为 `~`

- 优点：简单且具可读性。
- 缺点：`~/Library/Application Support` 仍然是 macOS 特有的语义，无法直接映射到 Windows 下的 `%APPDATA%`。
- 结论：否决。宿主专属目录必须依赖语义锚点。

### 持久化绝对路径，仅在 React 前端中进行缩写展示

- 优点：后端改动极小。
- 缺点：记录不具备可移植性，前端必须猜测用户的 Home 目录，且每次新增 UI 组件都可能不慎泄漏绝对路径。
- 结论：否决。展示层格式化无法弥补错误的持久化语义。

### 引入中间符号链接池（Intermediate symlink pool）

- 优点：所有链接集中在一个受控目录中。
- 缺点：增加了一层间接引用，并且违背了“将目标 App 目录直接单层软链接到真实源资产”的产品决策。
- 结论：否决。跨平台适配属于 `HostFilesystem` 的职责，不应引入额外的挂载拓扑。

## 后果

- 新增包含路径的配置字段时，必须明确声明其属于存储路径、解析路径、展示路径还是运行时观测数据。
- 代码在使用存储文本调用 `std::fs`、启动外部进程或向外部适配器发送请求前，必须显式调用 `expand_path`。
- 新增 DTO 时通常追加 `display_*` 字段而不是直接替换运行时字段，以保持 Reveal 功能与 Engine 协议的兼容性。
- Windows 上的符号链接失败能够向用户反馈明确可操作的“开启开发者模式/提升权限”提示。
- 路径规范化逻辑集中且便于纯单元测试，无需依赖真实宿主 OS 即可验证比较语义；原生 CI 仍用于验证 Windows 真实的符号链接行为。

# 0008: 适配器阶段前置数据降噪与命令输出裁剪策略

> 状态：已接受
> 决策日期：2026-08-09
> 决策证据：`76805340`, `72312fca`, `177074a7`
> 记录日期：2026-08-25

## 背景

在长时间的真实编码会话中，AI Agent 会频繁执行大量纯读取类命令（如 `cat` 大型源码文件、`find /`、`which` 探测、编译输出海量日志等），并伴随大量的 ANSI 终端转义序列。

如果原样存储这些无意义的原始终端输出，会导致：
1. 本地 SQLite 数据库体积急剧膨胀至数百兆甚至数 G，数据库性能急剧恶化。
2. FTS5 全文搜索索引被无价值的编译日志和重复源码占满，导致检索准确率断崖式下跌。
3. 后续 Memory 提炼与 AI 检索时耗尽 Token。

## 决策

1. **降噪前置至 Adapter 解析管道**：数据过滤与降噪的责任前移至外部适配器归一化阶段，严禁将未清洗的原始终端流写入 Core 存储。
2. **纯读取命令输出过滤**：对于 `cat`、`head` 等单纯读取文件内容的命令，丢弃其大体积 stdout 内容，仅保留命令文本与执行状态，防止源码在数据库中多副本膨胀。
3. **终端转义序列与 ANSI 清洗**：由 Adapter 负责去除 ANSI 控制符、转义光标代码和终端包装层。
4. **结构化 Diff 与结论提取**：对产生文件变更的命令，优先提取精简的结构化 Diff 片段；对长回答进行合理的保护性截断（Truncation），并在必要时提供完整查看通道。

## 备选方案

### 入库后再做异步清理（Post-processing Cleansing）

- 缺点：大体积日志已经写入了 WAL 和 FTS 索引，磁盘膨胀无法自动回缩；且入库过程本身消耗大量 I/O。
- 结论：否决。

## 后果

- SQLite 数据库体积下降 80% 以上，FTS 全文搜索索引质量与响应速度显著提升。
- 上层 AI 在检索历史记录时获得的均是高度浓缩、高信息密度的自包含结论。

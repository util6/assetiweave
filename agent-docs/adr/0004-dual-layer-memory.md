# 0004: 将 Memory 构建为独立的双层领域

> 状态：已接受
> 决策日期：2026-07-23
> 决策证据：`6e711c03dda11699cda907578d5eee8dcbb0d7f3`
> 记录日期：2026-07-23

## 背景

AssetIWeave 已经在 SQLite 中存储了规范化后的会话 Session、Question、Turn 和 Card，并可通过共享的会话搜索路径检索 Card。然而，用户还需要长期沉淀的结论（如偏好设置、架构决策、操作方法、上下文与待办跟踪），并且需要一种能够在不把整段会话归档一口气塞入 Prompt 的情况下回忆以往工作的机制。

如果将这些结论简单地作为目录资产 `AssetKind::Memory` 文件处理，将会丢失它们的证据关联（evidence relationships）、审查生命周期（review lifecycle）、新鲜度状态（freshness state）以及跨会话的作用域。如果仅使用单一的总结工作流，还会把两种截然不同的任务混为一谈：低成本的近期工作定向，与需要事实证据支撑的精准问答/长期归纳。

## 决策

- 将 Memory 建立为与 Conversations、Skills、Prompts、Rules 并列的独立一级产品领域。它拥有专属的 HeaderTab、SQLite 记录表、AppService 工作流、Engine 方法、CLI 命令以及前端服务。
- 保留 SQLite 中的规范化会话 Card 作为客观事实证据源。Dream 笔记、提取内容、问答结果以及正式的 Memory 条目均为派生记录，并保留对原始证据快照的引用链接。
- 采用两种互补的工作流：
  - **轻量级 Dream**：仅消费持久化游标之后的稳定会话增量，在通过时间、会话与并发锁门禁后生成简短、可审计的阶段性笔记。
  - **深度 Recall 与全量整理（Full Organize）**：构建证据包（evidence bundle），持久化有界的第一阶段提取结果，并通过受范围锁控制的第二阶段归纳生成附带引用来源的答案与待审查的候选记忆。
- 坚持以 SQLite 作为唯一的单一事实来源。不引入独立的 Memory Git 仓库、纯前端 Store、CLI 独立持久化路径或单独的 Card 索引。
- 默认关闭所有外部 AI 执行。用户必须显式配置并启用支持的本地 CLI/运行时之后，自动 Dream 或合成 Recall 才能将脱敏后的证据发送到应用程序进程之外。
- 严禁将 Dream 输出、模型生成内容或归纳候选条目直接提升为正式 Memory。正式条目必须通过手动创建或显式的“接受/编辑”操作以事务方式写入版本修订与证据引用。
- 桌面端、Engine、Go CLI 以及内置的 `assetiweave-memory` Skill 均通过共享的 `AppService` 工作流调用。Skill 仅用于组织对契约的调用，不重复实现持久化或归纳规则。

## 备选方案

### 复用 Catalog 中的 `AssetKind::Memory`

否决原因：扫描得到的文件是属于外部源的物理资产，而正式 Memory 是应用自有的派生知识资产，带有证据追溯、版本修订、新鲜度管理、冲突检测与审查状态。

### 将 Memory 作为 Conversations 的二级子页面

否决原因：正式 Memory 跨越了多个会话源和项目工程，拥有独立的生命周期，即使用户当前没有浏览某个具体 Session，Memory 也必须保持立即可用。

### 使用单一的全历史总结 Prompt

否决原因：无法真实报告覆盖率、重试代价极高、削弱了引用校验，且未能将轻量级的近期定向与强证据支撑的长期固化区分开。

### 自动将模型输出内容接纳为正式 Memory

否决原因：模型输出可能存在遗漏、提示注入、过时或自相矛盾的内容。自动接纳会把不可信的派生值在未经用户审核的情况下变成产品事实。

## 后果

- Memory 需要专用的数据库迁移、Repository、DTO、任务状态、配置项、前端界面、Engine/CLI 契约覆盖以及灾备恢复测试。
- 会话搜索与 Hydration 依然是第一证据路径；缺失的源通过有界快照进行明确说明，而不是静默丢弃。
- 外部 AI 调用需要确定性的数据脱敏、有界的输入/输出、结构化校验、进程取消机制、孤儿进程清理，并显式披露提供商/网络调用能力。
- 自动 Dream 仅可在会话同步后作为支持后台运行的后续检查触发。严禁在会话同步事务中运行 Dream，也严禁在模型 I/O 期间持有全局应用程序锁。
- 未来的 Memory 导出或向目标 App 的注入属于单独的显式挂载/导出决策，不包含在首期 Memory 模块发布中。

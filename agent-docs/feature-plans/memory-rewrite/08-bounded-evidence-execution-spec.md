## Problem Statement

用户需要内部 Memory 管线准确、低成本地提取可复用记忆，而不是把完整会话现场交给 Agent，再依靠 Skill 要求其自行筛选。

当前存在三个相互独立的成本来源：工具响应包含大量存储结构与重复正文；Agent 为理解现场反复读取；最终 Memory 在摘要、结果、分类列表与近期事件之间重复表达同一事实。只压缩最后输出或把大 Prompt 移入工具响应，都没有解决端到端信息成本。

已核对的内部 Session Memory 实现最多选择 512 项证据，每项携带正文与完整 locator；选择顺序按引用 key，而非会话时间或覆盖策略；执行请求没有 Session 专用读取工具。现有单项文本限制主要作用于生成输出，不是完整模型输入预算。高熵脱敏还可能误伤路径、符号和 Git SHA。

内部 ACP 执行已通过工作目录启发式在部分调度和近期入口排除，但这不等于完成导入、普通会话读取及检索的统一隔离。内部任务记录混入来源后，会降低检索质量并产生递归归纳风险。

用户 AIWC + Skill 实验中的具体 JSON 尚未提供。本规格不把该实验的冗余原因视为已定位事实，也不声明未经测量的 token 节省比例。交接中真实数据库的大 Prompt 观察是历史线索，不是本轮重新采样或可复现的基准结果。

## Solution

采用“系统准备精简证据包，Agent 判断记忆价值，仅为明确缺口补读”的内部生成方式。

系统负责范围、结构裁剪、去重、读取预算、完整性记录、引用映射和结果准入；版本化 Memory Recipe 负责提取重点与表达方式；Agent 负责语义判断，区分用户决定、Agent 提案、完成声明与验证证据。

首包只提供任务边界、用户意图及修正、结果证据、可补读索引。内部模型只接触短引用，不重复阅读数据库身份结构。按需工具同样返回高密度投影，而不是完整 Conversation Detail。

AIWC 保留用户主动探索的开放式数据面；软件内置管线保留自动、持久、增量维护的控制面。两者共享 AppService 下的证据读取能力，内部 Worker 不启动 AIWC 子进程。

Session Memory 保持结构化、可追溯、可重建。Project Memory 为主要长期知识层；Global Memory 只保留稳定跨项目信号。不再为每个 Session 自动生成重复 Markdown。

成功标准是：在关键事实、归因和覆盖质量不退化的前提下减少端到端模型成本；预算不足、证据缺失或结果不合格时，不把不完整结果发布为成功版本。

## User Stories

1. 作为用户，我希望内部 Memory 自动完成归纳，以便不必手动运行 AIWC。
2. 作为使用 AIWC 的用户，我希望手动探索与内置生成共享事实读取语义，以便同一现场不会产生两套解释合同。
3. 作为用户，我希望模型默认只接收判断所需的证据，以便减少无关 token 消耗。
4. 作为用户，我希望工具响应同样精简，以免大 JSON 只是从 Prompt 转移到了工具调用。
5. 作为用户，我希望必要时可以定点补读，以便精简输入不会牺牲关键上下文。
6. 作为用户，我希望用户请求和约束得到保留，以便后续 Agent 理解真正目标。
7. 作为用户，我希望后续纠正优先于早期设想，以免旧方案固化为长期记忆。
8. 作为用户，我希望 Agent 提案与已确认决定分开，以免建议被误记为共识。
9. 作为用户，我希望完成声明与实际验证分开，以免“声称通过”变成“已验证”。
10. 作为用户，我希望记忆保留有价值的失败原因和被否决方案，以免重复走弯路。
11. 作为用户，我希望未解决阻塞和待办保留状态，以便下次继续工作。
12. 作为用户，我希望缺乏证据时保持未知，以免模型补造结果。
13. 作为用户，我希望长会话不同语义问题均被纳入覆盖检查，以免只记住开头或结尾。
14. 作为用户，我希望来源已经截断或缺失时被如实记录，以免系统假装读到了完整现场。
15. 作为用户，我希望一个事实不在多个输出字段重复生成，以便记忆更紧凑。
16. 作为用户，我希望临时进展与长期偏好分开，以免 Session 细节污染 Global Memory。
17. 作为用户，我希望同一来源版本不重复生成，以便控制费用并避免重复近期事件。
18. 作为用户，我希望来源修订后记忆更新，以免继续采用被推翻的结论。
19. 作为用户，我希望删除和排除设置能传播到下游，以免不应再使用的内容继续出现在上下文。
20. 作为用户，我希望生成失败时继续读取符合有效性规则的 last-success，以便正常工作不被后台任务阻断。
21. 作为用户，我希望预算耗尽有明确状态，以便区分需要补充预算与真正没有可记忆内容。
22. 作为用户，我希望运行过程可取消、可恢复，以便管理长任务成本。
23. 作为用户，我希望编辑提取重点、忽略主题与表达风格，以便记忆符合我的工作方式。
24. 作为用户，我希望 Recipe 修改不会改变工具权限或持久化规则，以免提示词成为隐式授权。
25. 作为用户，我希望每次结果能追溯到实际使用的 Recipe 和合同版本，以便解释差异并重建。
26. 作为用户，我希望凭据在模型输入和持久化输出中均被脱敏，以免秘密进入长期记忆。
27. 作为用户，我希望路径、测试名、符号及 Git SHA 不被无依据地抹掉，以便记忆仍可指导开发。
28. 作为用户，我希望内部生成日志不混入普通 Conversation 和搜索，以便查到的是真正工作现场。
29. 作为 Recall 用户，我希望产品内持久 Recall 会话被保留，以免内部日志清理删除我的问答。
30. 作为用户，我希望 Session Memory 无需重复生成 Markdown，以便减少持久化与读取负担。
31. 作为用户，我希望 Project/Global 文档可由 SQLite 重建，以免文档损坏造成状态丢失。
32. 作为用户，我希望后台任务不锁住导航、筛选和无关操作，以便可以继续使用应用。
33. 作为多租户用户，我希望证据、短引用、预算及结果均绑定当前范围，以免跨租户或跨会话串读。
34. 作为维护者，我希望先建立成本与质量基线，以便判断优化是否真正有效。
35. 作为维护者，我希望区分 Fake Agent 的机制验证与真实模型的质量验证，以免用固定输出冒充总结能力证明。
36. 作为维护者，我希望旧数据清理先 dry-run、可备份、可回滚，以免误删用户来源事实。
37. 作为维护者，我希望 Engine、CLI、MCP 共享应用规则，以免维护多套裁剪、脱敏和权限逻辑。
38. 作为维护者，我希望每次只实现一个可验证切片，以便独立审查、提交和回滚。

## Implementation Decisions

### 1. 继承边界与规格修订

- 继承 Memory 合同 C-D01–C-X03 中未被本规格明确修订的内容；不扩大为通用 Team、云端 Memory 或新产品页面。
- Conversation 是来源事实；Question–Turn membership 是语义分组权威；Content Node 是 Part 的可定位投影；Card 仍仅为 UI 表现。
- AppService 是唯一业务编排边界，SQLite 是唯一结构化 Authority；Engine、Tauri、CLI、MCP 均为适配层。前端仍只经过 services。
- 项目目录仍按登记根目录、worktree、规范化 cwd 解析，不按 Git remote 合并；近期仍以 last activity 的滚动 72 小时为窗口。
- 单层直接软链接与来源只读原则不变；本规格不更改挂载策略。
- **对 Issue #20 的显式修订 A**：取消逐 Session Markdown 投影要求。Session 详细记忆和 source references 保存在 SQLite；Project/Global 长期文档仍是应用自有目录中的原子发布投影。
- **对 Issue #20 的显式修订 B**：将可编辑 Memory Recipe 纳入内置生成，但不引入第三方 Pipeline 安装、市场或自动信任远程 Skill。用户编辑行为不修改执行合同。
- **对 C-M01 的兼容要求**：保留目标、结果、决定、验证、阻塞、待办、主题、近期事件与来源引用的产品语义。内部模型输出可以变紧凑，不等于删除这些语义。
- ADR 0004 的 Engine/AppService Authority、ADR 0013 的 membership-first 投影继续成立。ADR 0008 的 Adapter 前置降噪与本规格的消费端精简是不同层；本规格不逆向恢复已被 Adapter 丢弃的正文，也不改写其源事实。
- 上述修订须在发布和进入实现前同步到父规格与相关合同，避免执行 Agent 同时面对冲突要求。已有 T01–T15 交付记录不是本增量的验收证据。

### 2. Evidence Kernel 与两种执行入口

- 在现有 Conversation 读取能力上形成 Memory 专用精简投影，不新建 Evidence 持久化产品或第二套 Conversation。
- 共享能力按语义覆盖：Session outline、范围内 search、Question 读取、Content Node 读取、locator 解析。正式方法名与 DTO 在对应契约切片生成，不把讨论名当作现有公开 API。
- AIWC 经 Engine 调用 AppService；内部 Orchestrator 经 AppService 与受限 ACP 读取工具调用同一能力，不通过 CLI 回环。
- 内部生成只绑定本 Job 的 tenant、Session 与 source revision；手动探索可使用自己的合法范围，不继承内部任务的写权限或自动入库语义。
- 不破坏普通 Conversation 详情接口，也不让 Go、Skill 或 MCP 各自实现一次裁剪器。

### 3. 精简证据包

- 首包固定包含：任务边界；用户意图与修正；结果及验证证据；可补读索引与覆盖状态。
- 系统保留角色、时间或顺序、Question 归属、证据种类及来源完整性，避免脱离说话者和否定上下文摘录。
- 默认不展开重复环境信息、重复 Skill 注入、整段源码、完整 diff、完整成功日志、Provider 调试元数据与数据库身份字段。
- “不展开”仅影响本次模型投影。对 canonical Conversation 中仍存在的内容保留有界补读入口。
- Adapter 已丢弃、截断或来源已缺失的内容明确标为不可用或不完整，不绕回 Provider 私有日志补采，也不把磁盘当前文件当作历史版本证据。
- 前置处理主要是确定性结构裁剪、去重、按角色与时间选取、已有结构化命令状态提取，不新增一次无界模型总结来制造首包。
- 纠正、否决、决定理由和失败链的语义判断交给 Agent；关键字匹配只能提供候选线索，不能宣告语义覆盖完整。
- 不默认装入整份 Project/Global Memory；Session 提取以本次来源为依据，跨 Session 合并与去重留给 Project Consolidation。

### 4. 短引用与模型传输合同

- 完整 locator、tenant、来源版本等由执行器保存；模型使用执行内短引用以及必要的角色、顺序和证据文本。
- 短引用绑定 Job 执行身份、source revision 和实际发给模型的摘录范围；只出现在索引中的身份不等于其正文已经被阅读。
- 补读返回同一映射中的引用；系统验证引用存在、在授权范围内、指向本次可用来源，并在提交前检查版本。
- 不允许模型通过猜测 node ID、拼接文件路径或更换 Session 标识扩大范围。
- JSON 保持可用，优化重点是字段和内容密度，不进行难维护的极短字段名或私有编码压缩。
- 引用存在性和结构验证不能证明自然语言蕴含关系；语义支持程度还需通过提取规则和质量评测验证。

### 5. 有界补读、覆盖与成本

- 覆盖以 canonical Question–Turn membership 和 source revision 为基础，记录已索引、已读、局部截断、未读、不可用的范围，不能用“工具调用成功”替代覆盖判断。
- Agent 补读应针对具体疑问，例如后续是否推翻、决定是否确认、验证是否存在。工具端强制范围和预算，不依赖 Agent 自觉停止。
- 每项正文、每次响应、首包、累计工具响应、模型输出、工具调用次数、执行时间和 Job 总工作量均有独立上限。
- 索引、工具定义、Recipe 和重复发送的对话上下文计入成本；长会话分段后的聚合调用与重试同样计入，不能通过分批重置总预算。
- 长会话按有界 Question/Turn 窗口提取并在同一来源版本下合并；超长单项通过可定位分片读取，保留顺序、上下文和截断标记。
- 引擎可以证明范围已处理，不能机械保证每条语义都被正确记住。最终成功还要求输出验证与质量门槛。
- 未覆盖完整或预算耗尽时保存执行进度及原因，不发布部分 Session Memory 为 last-success，不进入 Project/Global 成功输入集合。
- 对确定性的预算不足不无限自动重试；仅来源、策略或预算变化后重建，或由用户显式重试。暂时性执行错误沿用有限退避重试。
- 具体数值由首个基线切片校准并冻结为版本化产品策略；没有既有测量时不把任意数字或节省比例写成已确认需求。冻结是后续切片的硬 blocker。

### 6. Memory Recipe 与固定 Execution Contract

- Recipe 控制记什么、忽略哪些主题、项目术语、表达方式和记忆价值准则；不控制 tenant、工具白名单、预算、输出准入、数据库写入、失效和任务生命周期。
- 记忆价值准则：优先保留能减少下次重复提问、调查或错误的事实；Session 层同时保留恢复工作所需的短期状态，不要求每项都提升为长期知识。
- 每次运行绑定 Skill 资产身份、Recipe revision、content hash、Memory contract version、projection policy version 和预算策略版本。
- Work Order 是绑定上述身份和 source revision 的执行描述，不构成第二套任务调度实体；持久身份与进度仍归属 SQLite Job。
- Recipe 变更形成新的输入 fingerprint 并按既有失效机制重建；正在运行的任务使用已固定快照，其旧版本结果不覆盖新目标水位。
- Agent/model assignment 与实际运行身份用于归因记录；更换模型本身不自动触发全部历史重建，显式重建可选择新 assignment。
- 所有 Conversation 文本、工具结果和 Recipe 文本都不是权限授予渠道；产品固定合同优先于其中的越界指令。

### 7. 一次提取事实，生成多个可读投影

- 提取器输出有界的事实集合；每项包含正文、语义类别、状态与证据引用，必要时包含被替代关系和适用范围。
- 状态至少区分用户已确认决定、Agent 提案、声称完成、证据支持的验证、未解决事项。没有证据时留空或明确未知，不为填满 Schema 生成内容。
- 程序把单份事实组织到既有 Session Memory 和 Recent Event 语义，不再要求模型在摘要、结果及事件中完整复述同一内容。
- 摘要采用有界事实投影；目标/结果、分类列表与事件可以引用或组织相同事实，但不制造第二套独立、可冲突的事实权威。
- 初期保留现有外部读取语义；内部提取 DTO 与持久 Schema 若发生变化，通过版本化合同与追加 migration 完成，不静默删字段。
- 无可提取内容与读取未完成是不同结果。覆盖完成且合格输入为空可得到明确无内容终态，不产生虚构 Memory 或近期事件。
- Project Consolidation 只消费成功且符合有效性规则的 Session Memory，合并冲突、替代关系与引用；Global 只消费成功 Project Memory，保留跨项目稳定偏好、工作方式及索引。
- 不把单次 Session 的局部偏好默认提升成全局规则；也不把多次机器重复描述当作多份独立证据。

### 8. 内部执行隔离与历史数据处理

- 采用显式执行来源、执行用途和用户可见性，不再仅靠目录名识别内部执行。具体列或登记结构通过追加 migration 与现有执行登记接缝确定。
- 执行登记发生在可能生成 Provider 记录之前；导入匹配优先使用执行/会话关联身份，路径只能作为历史审计辅助信号。
- 来源识别与导入适配留在 Adapter/执行集成边界；Memory 仅消费 canonical 标记，不解析 Provider 私有格式。
- 内部生成记录不进入普通 Conversation 列表、普通搜索/FTS、Recent Work、Memory 调度、Evidence 读取和 Recall 候选集合；分页总数也使用相同过滤规则。
- 产品创建的持久 Recall 问答仍按现有 Conversation 合同保留并可从 Recall 工作流访问；不得因内部运行记录清理而删除，也不作为递归 Memory 输入。
- 历史清理先审计与 dry-run，列出证据强度、影响计数、下游索引及 Memory 失效计划；只处理可证明属于内部执行的数据。
- 默认优先标记、隔离和重建派生索引，不物理删除来源事实；需要破坏性 apply 时另行确认，并在经过验证的备份之后执行。
- 重复执行清理必须幂等；归属不明数据保持原样，不凭目录碰巧同名推断用户记录。

### 9. 脱敏与受限执行

- 模型首包、补读结果及最终入库结果均执行秘密脱敏；明确秘密格式与凭据上下文优先，高熵仅作辅助信号。
- 对长路径、测试名、符号、Git SHA、随机标识和真实凭据建立正反样本，不通过全局关闭脱敏修复误伤。
- 无无关网络访问、协作 Agent、递归 Memory、无关插件或宿主通用文件读取；受限工具只读 canonical Conversation。配置 ACP 模型所需的通信不等于授予 Agent 额外网络工具。
- 应用控制结果提交和投影发布。若执行器需要临时产物，仅落在应用自有隔离 workspace，不写来源目录。
- 日志、公开错误和任务快照不包含 Prompt、正文、原始工具输入、凭据或环境变量值；执行遥测只保存预算、计数、阶段、版本和非内容错误分类。
- 若所选 ACP 后端不能落实所需隔离或工具限制，应给出明确执行配置错误，不把 Skill 中的文字限制当作已生效隔离。

### 10. Durable Job、版本与恢复

- 保持 Conversation commit → Outbox → durable enqueue → consumer ack → Worker 的顺序，Consumer 不直接运行模型。
- 保持完成信号或 30 分钟 idle 门、cutoff/backfill、启动漏单扫描、lease、ownership token、heartbeat、retry、cancel、shutdown 与目标水位合并。
- Phase 1 跨 Session 有界并发、同 Session 串行；Project 按规范化目录串行、不同项目可并行；Global 轻量串行。三者使用独立 action assignment。
- 追加 Recipe/投影策略身份不得破坏幂等：同一有效 fingerprint 至多一个成功 Phase 1 结果；同一来源的策略升级通过版本规则显式产生新目标。
- 来源修订、删除、缺失、迁目录、排除或合同变更发生于补读/提交期间时，旧执行不发布为新版本，也不提升下游 watermark。
- 重启后恢复已持久化的同版本进度；短引用映射可确定性重建或受控恢复，不能让一次旧执行的短引用解析到新内容。
- Agent 调用、读取与写文档不持有全局应用锁；TaskRuntime 只作活动投影，SQLite 保存任务与成功版本 Authority。
- last-success 保持非阻塞读取，但不绕过 tenant、删除和排除等有效性约束。失败与取消不覆盖成功快照；显式失效内容不因“最后成功”重新可见。

### 11. 存储、公开表面与发布

- Session Memory、来源引用、版本、coverage、进度和失效信息保存在 SQLite；只持久化恢复/审计必需的执行元数据，不额外保存完整模型 Prompt 副本。
- Project/Global Markdown 从 SQLite 生成，使用临时文件、验证和原子替换；文档损坏可重建，文档不成为新的读取 Authority。
- 保留现有 Recent、Context、Project、Rebuild、Task 与 Recall 公共能力和结构化引用跳转；不新增 Evidence/原始 JSON 管理页面。
- 内部 MCP 的 Job token 与用户 Engine 的访问范围分别验证；自动化用户可请求合法只读投影，但不能据此伪造后台提交。
- 新增或变更 Engine 方法、DTO、错误及暴露范围时运行 `pnpm cli:contract`，保证连续生成一致；不手改生成契约。
- 现有 MemoryTaskProvider 与统一后台 Provider 继续承载事件订阅和 polling fallback；完成时聚合刷新，进行中只禁用冲突操作。
- 不维持长期旧/新生成双轨；以合同版本切换，旧成功数据按失效策略处理。回滚策略不包含重新激活旧的内部记录污染入口。

## Testing Decisions

### 主测试接缝与既有先例

**待用户确认：以 AppService + 临时 SQLite + 可控时钟 + Fake AgentExecutor 为唯一主要业务验收接缝。** 从 canonical Conversation 提交、调度或公开读取入口进入，断言公开可读 Memory、Recent/Context、状态、引用及数据库重开后的行为，不绑定私有函数、具体 SQL 或内部锁实现。

已有先例包括 Phase 1 的 idle/脱敏/幂等集成测试、Session 运行时设置快照测试、内部工作区排除测试、Project/Global last-success 测试、Conversation 同步与 Outbox、TaskRuntime 恢复测试。

仅为主接缝覆盖不到的边界复用：现有 Fake ACP 验证工具装配、预算拒绝、取消、退出与隔离；现有 Engine/CLI surface 验证适配一致性；现有 frontend service/component 测试验证状态与导航。小型脱敏/裁剪纯函数测试用于边界样本，不代替高层验收。

### 必须覆盖的行为矩阵

| ID | 输入与公开动作 | 可观察验收 |
|---|---|---|
| E01 | 同事实附带大量重复环境与源码输出后生成 | 模型可见首包和读取均有界，原 canonical 事实不变 |
| E02 | 用户先提议后否决，Agent 最后仍复述旧方案 | 输出不把旧方案记作已确认；修正与理由可追溯 |
| E03 | Agent 声称通过，但没有验证输出或有失败结果 | 保留声称/验证的区别，不生成虚假通过结论 |
| E04 | 长会话含多个 Question，关键纠正在中段，单项超长 | 索引/分段覆盖不偏向首尾；分片可定位且没有静默截断 |
| E05 | 提交未知、跨 tenant、跨 Session、旧 revision 或未读正文引用 | 明确失败，不持久化成功 Memory，不泄漏范围外存在性 |
| E06 | 连续读取、重复读取、重试或跨分段耗尽预算 | 总量上限生效，原因可见，不无限重试，不把部分结果提升成功 |
| E07 | Adapter 已丢弃正文、来源缺失、或证据包为空 | 明确区分不可用、未读、无内容，不回读私有日志或伪造历史 |
| E08 | 提取有效事实并投影到摘要/事件 | 必需语义可读且事实不重复生成，引用可跳转；无内容不制造事件 |
| E09 | 读取中修改来源或 Recipe，再让旧任务晚到 | 旧结果不覆盖新目标；同 fingerprint 重放不重复提交 |
| E10 | 运行中 cancel、lease 过期、退出、重启 | 重开数据库后状态可恢复，预算及 coverage 不无界重置 |
| E11 | 来源修订/删除/缺失/迁目录/排除/合同升级 | Session → Project → Global、Recent、索引和投影失效一致 |
| E12 | 插入内部生成记录、用户普通记录、产品 Recall 问答 | 列表、计数、FTS、Recall 候选、调度和补读统一隔离；Recall 工作流记录保留 |
| E13 | 历史记录归属不明、路径同名、多次执行 dry-run/apply | 不误标普通记录；处理幂等，备份/恢复可验，下游派生内容同步失效 |
| E14 | 输入包含真实凭据和路径、符号、SHA 正反样本 | 凭据不出现在模型输入/结果/日志，非秘密标识保持可用 |
| E15 | Recipe 或证据要求扩权、跨范围、访问外网、递归生成 | 产品限制生效；后端能力不足明确失败，不靠提示词宣称隔离 |
| E16 | 经 Engine/CLI 与内部 MCP 请求同一合法投影 | 内容与引用语义一致；各自授权生效；内部不启动 AIWC |
| E17 | Project/Global 文档损坏或发布失败 | SQLite last-success 按有效性规则可读，投影可重建，无逐 Session Markdown 依赖 |
| E18 | 后台任务中浏览、筛选、取消，观察事件与轮询 | 无关操作可用，状态一致，取消与失败不触发虚假完成刷新 |

### 成本与质量评测

- 在同一固定 fixture 集上比较当前全文方式、仅索引补读、精简证据包加补读，记录各自覆盖范围；当前 512 项截断造成的遗漏不能当作“等质量”基准。
- Fixture 至少涵盖短会话、工具密集会话、多问题长会话、否决/纠正、验证矛盾、低价值会话、超长单项、秘密与非秘密混合、版本变动及内部记录污染。
- 人工标注应保留的事实、禁止推断的事实、支持片段、状态与适用范围；基线报告记录误归因、关键遗漏、无依据结论、重复信息及后续恢复任务表现。
- 单独报告首包体积、工具响应体积、完整执行输入/输出 token、调用数、耗时、失败率和重试开销；缓存命中与计费 token 单列，不用字符数假装精确 token。
- Provider 不报告 token 时明确使用估计值及算法版本；端到端成本记录包含重复上下文与分段归并。精确计数不可得不等于零成本。
- Fake Agent 证明投影、权限、预算、状态与准入机制；真实模型语义质量通过显式开启的隔离评测验证，固定模型/配置并重复运行，不能用 Fake 固定输出替代。真实 Provider 不属于自动化 CI 的必要依赖，但在声明总结质量达标、成本优化可发布之前必须补齐该评测；未运行时只能交付机制验证，不能关闭质量门禁。
- 真实模型评测默认只用合成或已脱敏且获准的 fixture，不在本轮调用真实 Provider，也不读取用户数据库作为自动化依赖。
- E0 切片必须冻结数值预算、比较配置、成本目标及质量容差并保存依据。关键纠正、归因和验证错误的标注样本必须通过；其他指标按冻结门槛判定，失败不得用继续砍输入掩盖。

### 验证门禁

- 各切片沿用 G0–G7 中适用门禁，最终切片运行 G8，并覆盖本规格 E01–E18；命令的输出、退出码和实际测试数量进入交接。
- Rust：`cargo fmt --all -- --check`、相邻过滤测试及 `cargo test --workspace`；零匹配不算通过。
- CLI/契约：`pnpm cli:contract` 连续生成一致、`go vet -C cli ./...`、`go test -C cli -race ./...`、`pnpm check:surface-matrix`，必要时运行 `pnpm cli:test:e2e`。生成与 E2E 使用临时数据库。
- 前端：涉及公开 DTO、任务状态或可见性时运行相关 service/component/navigation 测试；最终运行 `pnpm typecheck`、`pnpm test`、`pnpm build`。
- 架构与 Skill：`pnpm check:boundaries`、`pnpm test:boundaries` 及现有 Memory Skill 测试；旧词 grep 按历史 migration/内部证据术语/旧公开语义分类，不机械要求 evidence 单词零命中。
- 追加 migration 必须在临时旧 schema 上升级验证；历史 checksum 不改写。运行基线遵守 Node 22、pnpm 10、Go 1.24、Rust 1.96.0+。
- 桌面人工验证补充响应性、关闭提示和持久 Recall 恢复；未运行项明确列出，不复用历史 PASS 声称本增量完成。

## Out of Scope

- 本轮生产实现、真实用户数据库变更、历史记录删除、真实 Provider 成本实验及自动提交。
- 通用 Team、多 Agent 协作、云端/跨设备 Memory、知识图谱和新的 Evidence 管理界面。
- 重写所有 Conversation Adapter，恢复其已经丢弃的原始终端输出，或由 Memory 读取 Provider 私有日志。
- 使用 AIWC 子进程作为内置 Worker，或在 Go、Skill、MCP 中复制业务规则。
- 全文先交给另一个无界模型压缩、无限自主检索、只缩短最后输出而不测总成本。
- 完全替换产品执行合同的用户 Skill、第三方 Memory Pipeline 市场和自动信任远程 Recipe。
- 默认给 Session 提取器注入整份历史 Project/Global Memory，或自动向外部宿主原生 Session 注入 Memory。
- 将逐 Session Markdown、模型原始 Prompt 或新 Evidence 文档集合提升为 Authority。
- 顺带处理 ACP 连接/模型发现缓存、通用后端基础设施收口、其他 UI 修改或现有工作区未提交内容。

### 每轮执行规则

1. 读取仓库约束、父规格/当前子 Issue 的最新评论、Memory router 与当前唯一执行卡；只加载相关 Contract、Seam 和 Gate。

3. 依次执行 Locate → Baseline → Red → Minimal → Converge → Verify → Review → Commit → Handoff；缺少目标行为失败证据时不写生产实现。
4. 优先复用现有 TS01–TS07；每项验收写成“输入 → 公开动作 → 持久/可见结果”，不以私有调用次数代替行为。

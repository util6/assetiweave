## Ticket / Status

写本轮唯一 Ticket ID，以及 VERIFIED 或 BLOCKED。

## Baseline / Scope

写起始和结束 revision；脏工作区以 patch/具体文件归属补充。列修改文件、安装版本、生产消费者切换和已删除机制。

## Contract / Evidence

列涉及的 C-*，是否变更外部协议/生成物。每条验证写完整命令、退出码、测试数、关键断言与执行平台；失败/跳过分别列出。记录检查源码与实际运行的区别。

## Review

列审查发现及处理结果；解释保留的业务机制与必要薄适配。若遗留过渡导出，明确剩余调用方及负责删除的 Ticket ID。
